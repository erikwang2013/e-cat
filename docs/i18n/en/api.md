# Ecat API Reference

This page summarizes the API surface of the Ecat framework: port conventions, built-in endpoints, error formats, and extension interfaces. Business routes are registered by each service itself.

## Port Conventions

| Protocol | Listen address | Notes |
|------|----------|------|
| HTTP | `0.0.0.0:8000` | axum routes, default example port |
| gRPC | `0.0.0.0:9000` | tonic Server, default example port |

## Built-in Endpoints

The following endpoints are provided by ecosystem crates and mounted with the service:

| Endpoint | Source | Notes |
|------|------|------|
| `/health` | ecat-health | Liveness check (returns service name, version, start time) |
| `/ready` | ecat-health | Readiness check (returns 200 once dependencies are ready) |
| `/metrics` | ecat-metrics | Prometheus metrics exposure (`ecat_http_requests_total` / `ecat_http_request_duration_seconds`) |
| `/{service}/{method}` | User routes | Example: `/helloworld/ecat` |

> For high-cardinality scenarios where metric endpoint paths contain IDs, use `MetricsLayer::new().with_path_fn(...)` to normalize and avoid metric cardinality explosion.

## Request Handling Flow

```
客户端请求
  ├─ HTTP :8000 ──→ axum::Router ─┐
  └─ gRPC :9000 ──→ tonic::Server ─┤
                              ┌─────┴──────┐
                              │ Middleware │  Recovery→Tracing→Logging→Auth→Metrics→Security→CircuitBreaker
                              └─────┬──────┘
                                    ▼
                               Handler（tower::Service）
                                    ▼
                               Response（JSON/Protobuf 编码）
```

## Error Format

`ecat-errors` provides `ErrorCode` + `Error` with compile-time HTTP status mapping:

```rust
use ecat_errors::{Error, ErrorCode};

Error::new(ErrorCode::InvalidArgument, "bad_request", "user id must be positive");
```

Error responses are encoded as JSON (or Protobuf) by middleware, carrying code / reason / message.

## Extension Interfaces

| Capability | Crate | Interface |
|------|-------|------|
| GraphQL | ecat-graphql | `/graphql` endpoint; supports field arguments and nested selections, does not support aliases, fragments, or multiple top-level fields |
| OpenAPI | ecat-openapi | Generate OpenAPI spec from routes |
| WebSocket | ecat-transport-ws | Upgraded WS transport |
| API version routing | ecat-versioning | `/v1/...` prefixed version routes |
| Authentication | ecat-auth | JWT / API Key middleware; JWT secret must be ≥32 bytes, chainable `required_issuer`/`required_audience` |
| gRPC client | ecat-transport-grpc | Integrated service discovery and load balancing |

## Inter-service Communication

- `HttpClient` (ecat-client): integrates service discovery and load balancing, with CircuitBreaker protection
- `GrpcClient` (ecat-transport-grpc): same, over the gRPC protocol
- Middleware is uniformly composed via `tower::ServiceBuilder` (Recovery / Tracing / Logging / Timeout / RateLimit / Security / CircuitBreaker / Metrics / Retry / Validate / CORS)

## Data Backend Interfaces

All data backends (`ecat-data-*`) are abstracted through unified traits (`RdbmsClient` for transactions and `SqlExecutor` for execution/dialect / `Cache` / `SearchClient` / `GraphClient` / `TsdbClient` / `DocumentClient` / `StorageClient`); REST-style backends (Neo4j / NebulaGraph / ArangoDB / InfluxDB / IoTDB / QuestDB / TDengine / OpenSearch / Elasticsearch / S3) access their corresponding HTTP interfaces via `base_url`. Connection configuration: see [Database Configuration Tutorial](database-config-tutorial.md).

## ORM (ecat-orm)

`ecat-orm` provides an entity derive macro, a type-safe query builder, CRUD, relation preloading and
migrations. Every data operation takes `&impl SqlExecutor`, so the **same API works with a client and
with a `Transaction`**:

```rust
User::find_by_id(&db, 1).await?;              // db: SqlxClient / MssqlClient
let tx = db.transaction().await?;
User::update(&tx, &user).await?;              // tx: Transaction
User::insert(&tx, &user).await?;              // works inside a transaction: both statements run there
tx.commit().await?;
```

SQL is generated by the dialect layer: SQLite / PostgreSQL / MySQL / TiDB (`ecat-data-sqlx`) and
SQL Server (`ecat-data-mssql`) share one entity definition.

### Entity definition and the `#[entity(...)]` attribute grammar

`#[derive(Entity)]` generates `Entity::META` (table / columns / relations / flags), `from_row` /
`to_values` / `pk_value`, plus one `XxxRelation` enum per entity (variant names are the PascalCase of
the relation field names).

Container attribute:

| Syntax | Meaning |
|------|------|
| `#[entity(table = "users")]` | Table name; when omitted, the snake_case of the struct name (`User` → `user`, `UserProfile` → `user_profile`) |

Column fields:

| Syntax | Meaning |
|------|------|
| `#[entity(column = "user_name")]` | Column name override, defaults to the field name |
| `#[entity(pk)]` | Primary key |
| `#[entity(auto_increment)]` | Auto-increment (implies pk); the auto-increment key is left out of the insert column list and generated by the database |
| `#[entity(created_at)]` / `#[entity(updated_at)]` | Automatic timestamps: both are filled on insert, only `updated_at` is refreshed on update |
| `#[entity(soft_delete)]` | Soft-delete column: the read path adds an `IS NULL` gate on it automatically |
| `#[entity(version)]` | Optimistic-lock column: updates write `version + 1` and compare against the old value, conflicts return `OrmError::OptimisticLockConflict` |

Relation fields (**the container type is a hard constraint**; a bare entity type is rejected at
compile time — it cannot express "not found"):

| Syntax | Field type | Meaning |
|------|----------|------|
| `#[entity(has_many = "Post", foreign_key = "user_id")]` | `Vec<Post>` | One-to-many: this table's `local_key` value is matched against the target's `foreign_key` column |
| `#[entity(has_one = "Profile", foreign_key = "user_id")]` | `Option<Profile>` | One-to-one; a single-valued relation takes the first row only |
| `#[entity(belongs_to = "Tag", foreign_key = "tag_code")]` | `Option<Tag>` | Many-to-one: this table's `foreign_key` value is matched against the **target's primary key** |

`local_key` may be omitted: `has_many` / `has_one` default to this table's primary key, `belongs_to`
defaults to the target's primary key. Relation fields **are not columns**. The mapping from a field
type to a column type lives only in the `value::ColumnValue` impls (the macro keeps no second copy of
that table); an unsupported type produces an unsatisfied `T: ColumnValue` error pointing at that field.

### CRUD

| Method | Notes |
|------|------|
| `Entity::insert(&db, &e) -> i64` | Inserts and returns the new primary key. MySQL's two-step path (`INSERT` then `SELECT LAST_INSERT_ID()`, which is **connection-scoped**) is wrapped into a single transaction by `SqlExecutor::execute_then_query` |
| `Entity::insert_many(&db, &[e]) -> u64` | Bulk insert, returns affected rows (no keys back: `LAST_INSERT_ID()` gives the first row, SQLite the last — unreliable across backends) |
| `Entity::save(&db, &e)` | Inserts when the primary key is "unset" (auto-increment and equal to 0), otherwise updates; returns `()` |
| `Entity::update(&db, &e) -> u64` | Full-row update by primary key. Zero affected rows is an error: `OrmError::NotFound` without a `version`, `OrmError::OptimisticLockConflict` with one (without an extra query the two are indistinguishable) |
| `Entity::update_many(&db, &[e]) -> u64` | Row-by-row update, returns the summed row count; a bulk call **cannot tell you which row** conflicted (a result smaller than the input means one was stopped by the version gate) |
| `Entity::upsert(&db, &e) -> u64` | Upsert by primary key (per-dialect `ON CONFLICT` / `ON DUPLICATE KEY` / `MERGE`) |
| `Entity::find_by_id(&db, pk) -> Option<Self>` | Fetches one row by primary key, returns `Ok(None)` when absent |
| `Entity::find_all(&db) -> Vec<Self>` | All rows with no filtering (**a full table scan on large tables**; use `paginate` for paging) |
| `Entity::delete_by_id(&db, pk) -> u64` | With `soft_delete` declared it issues an `UPDATE` setting the deletion timestamp; the row stays in the table, and deleting again returns `NotFound` without refreshing the timestamp |
| `Entity::hard_delete_by_id(&db, pk) -> u64` | Bypasses soft delete and really issues `DELETE` |

### Query builder

Start with `User::query()`, which returns `Query<User, Unfiltered>`; adding a filter turns it into
`Query<User, Filtered>` (type state) — "delete without a WHERE" does not compile.

```rust
use ecat_orm::query::{Op, Order};

let users = User::query()
    .filter("name", Op::Like, "alice%")?        // Eq / Ne / Lt / Le / Gt / Ge / Like
    .filter("email", Op::NotNull, serde_json::json!(null))?
    .filter("id", Op::In, serde_json::json!([1, 2, 3]))?  // In / NotIn take an array value
    .order_by("id", Order::Desc)?
    .limit(10)
    .offset(20)
    .fetch(&db)
    .await?;
```

- Column names are checked against the `EntityMeta.columns` whitelist (`OrmError::UnknownColumn`);
  columns of joined tables are not in that whitelist — use `filter_raw("...")` for them, and note it
  performs **no validation at all, so the input must be trusted**.
- `with_trashed()` disables the soft-delete gate (rows that were soft-deleted come back too).
- `join(JoinType::Left, "posts", "posts.user_id = users.id")` supports `Inner` / `Left`, and is meant
  for filtering on a joined table's columns inside `filter_raw`. The **column list carries no table
  prefix**, so if the joined table shares a column name with the subject, the real database reports
  `ambiguous column name` — join on tables whose column names differ from the subject's (verified on
  SQLite).
- `delete_where(&db)` / `hard_delete_where(&db)` delete by the same conditions (soft-delete entities
  go through `UPDATE`).
- `fetch(&db)` is the execution entry point; `find_by_id` / `find_all` / `paginate` all reuse the same
  SQL generation path behind it.

### Chunking and pagination

- **Bulk writes chunk automatically**: `insert_many` / `update_many` split by the dialect's
  per-statement parameter limit (e.g. 2100 on SQL Server) and sum the row counts. To chunk manually,
  use the same limit: `ecat_orm::dialect::lookup(dialect).max_params_per_stmt()`.
- **Pagination**: `paginate(&db, page, per_page)` issues 2 queries (COUNT + page fetch) and pages are
  **1-based**; COUNT reuses the same WHERE / JOIN but drops ORDER BY / LIMIT / OFFSET. It returns
  `Page { items, total, page, per_page }`, and `total_pages()` / `has_next()` are derived from `total`.
- For deep paging over large tables use `paginate_without_count(&db, page, per_page)` (1 query):
  `total` is `None`, and `total_pages()` / `has_next()` cannot answer either — what cannot be computed
  is reported as such instead of guessed.

### Relation preloading

```rust
let users = User::query()
    .with(&[UserRelation::Posts, UserRelation::Profile])
    .fetch(&db)
    .await?;
```

- Each relation issues **one** `IN` query (chunked when the keys exceed the per-statement parameter
  limit), and the subject query itself does not join — **no N+1**: fetching 3 users and their posts is
  2 SELECTs (1 subject + 1 `IN`), not 4.
- Without `with()` the relation fields are empty (`Vec::new()` / `None`), never stale values from a
  previous load; `set_relation` is called for every subject (including empty results) precisely to
  clear leftovers.
- Single-valued relations (`has_one` / `belongs_to`) take the first row only.

### Migrations

```rust
use ecat_orm::migrate::drop_table_sql;
use ecat_orm::{Migrator, create_table};

Migrator::new(&db)
    .add("001_users", create_table::<User>().with_reverse(|d| drop_table_sql(User::META, d)))
    .add("002_posts", create_table::<Post>())
    .status().await?;      // MigrationStatus { applied, pending, unknown }
    .run().await?;         // applies pending migrations, records each in the version table; re-running is idempotent
    .down(1).await?;       // runs 001's reverse SQL and removes that row from the version table
```

- The numeric prefix of a migration name is its version (`"001_users"` → 1); a non-numeric prefix
  raises `OrmError::InvalidMigrationName` — it is never guessed as 0.
- `create_table::<E>()` / `drop_table::<E>()` generate DDL from `EntityMeta`, and **the dialect is
  resolved at `run()` time from the connection's `dialect()`**, so the migration list is decoupled
  from the connection string. Custom SQL (ALTER, data backfills) uses
  `ecat_orm::migrate::MigrationBuilder::new(|d| ...)`.
- Calling `down` on a migration without reverse SQL raises `OrmError::MigrationIrreversible` —
  "DROP then CREATE it back" loses data, and that is not guessed on the caller's behalf.
- The version table is created automatically by `Migrator` (MSSQL has no `CREATE TABLE IF NOT EXISTS`,
  so existence is checked first).
