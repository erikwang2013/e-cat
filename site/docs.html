安装与使用 Ecat

从 cargo install 到运行中的 HTTP 与 gRPC 服务。示例与仓库 examples 使用同一套 API。

让服务跑起来

四个具体步骤。右栏保留完整命令序列。

准备 Rust 与 protoc

Ecat 使用 edition 2024，需要 Rust 1.85 或更新版本。CLI 和生成的代码还需要 protoc。

terminal
# Ubuntu / Debian
sudo apt install protobuf-compiler

# macOS
brew install protobuf

# verify
rustc --version
protoc --version

安装 CLI

从 crates.io 安装。二进制随包携带宠物资源与 ASSETS-LICENSE 说明。

terminal
cargo install ecat-cli
ecat --version

创建服务

创建项目，添加 proto 文件，再生成客户端与服务端代码。生成的 build.rs 已接好 tonic-build。

terminal
ecat new helloworld
cd helloworld
ecat proto add proto/service.proto
ecat proto client proto/service.proto
ecat proto server proto/service.proto -t internal/service

运行

默认 HTTP 服务监听 0.0.0.0:8000。使用 --watch 在 src/ 变更时重启。

terminal
ecat run
ecat run --watch
完整快速开始
# 脚手架
ecat new helloworld
cd helloworld

# 添加 proto
ecat proto add proto/service.proto

# 生成客户端与服务端
ecat proto client proto/service.proto
ecat proto server proto/service.proto -t internal/service

# 运行
ecat run

把整段命令复制到 shell。生成的服务地址是 http://localhost:8000/helloworld/ecat。

terminal

使用各个部件

聚合 crate 按 feature 重新导出模块，只启用服务用到的部分。

应用生命周期

AppBuilder 组合服务器、生命周期钩子和信号处理。run() 阻塞到 SIGTERM 或 SIGINT。

  • HTTP 与 gRPC 服务监听不同端口。
  • on_start 与 on_stop 钩子是异步的。
  • 聚合 crate 让导入路径更短。
main.rs
use ecat::App;
use ecat_transport_http::HttpServer;
use ecat_transport_grpc::GrpcServer;

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error + Send + Sync>> {
    let app = App::builder()
        .name("my-service")
        .version("v1.0.0")
        .server(HttpServer::new("0.0.0.0:8000"))
        .server(GrpcServer::new("0.0.0.0:9000"))
        .on_start(|| async {
            tracing::info!("service started");
            Ok(())
        })
        .on_stop(|| async {
            tracing::info!("service stopped");
            Ok(())
        })
        .build()?;

    app.run().await?; // 阻塞到 SIGTERM 或 SIGINT
    Ok(())
}

组合中间件

每个 layer 都是 tower::Layer。顺序有影响：恢复与追踪在外层，认证与安全靠近 Handler。

  • JWT 密钥至少 32 字节。
  • 超时与熔断保护下游调用。
  • SecurityLayer 阻断高风险请求模式。
middleware.rs
use tower::ServiceBuilder;
use ecat_middleware::{RecoveryLayer, TracingLayer, LoggingLayer, TimeoutLayer};
use ecat_circuit_breaker::CircuitBreakerLayer;
use ecat_security::SecurityLayer;
use ecat_auth::JwtAuthLayer;
use std::time::Duration;

// JWT 密钥至少 32 字节
let jwt = JwtAuthLayer::new("change-me-32-bytes-minimum-secret")
    .expect("valid jwt secret");

// 顺序有影响
let layer = ServiceBuilder::new()
    .layer(RecoveryLayer)
    .layer(TracingLayer)
    .layer(LoggingLayer)
    .layer(TimeoutLayer::new(Duration::from_secs(30)))
    .layer(CircuitBreakerLayer::new())
    .layer(jwt)
    .layer(SecurityLayer::new());

连接数据后端

每个后端都有 XxxConfig 与 from_config()。Redis、SQLx、ClickHouse 和其余后端形状一致。

  • 配置可以来自 JSON 或 YAML。
  • 出站超时与熔断按 client 配置。
  • feature 名与后端名对应。
data.rs
use ecat_data_redis::{RedisCache, RedisConfig};
use ecat_data_sqlx::{SqlxClient, SqlxConfig};
use std::time::Duration;

// 从 JSON 或 YAML 加载配置
let config: serde_json::Value = serde_json::from_str(r#"{
    "redis": {"url": "redis://localhost:6379"},
    "sql":   {"url": "postgres://user:pass@localhost/db"}
}"#)?;

// Redis
let redis_cfg: RedisConfig = serde_json::from_value(config["redis"].clone())?;
let cache = RedisCache::from_config(redis_cfg).await?;
cache.set("key", b"value", Duration::from_secs(60)).await?;

// RDBMS
let sql_cfg: SqlxConfig = serde_json::from_value(config["sql"].clone())?;
let db = SqlxClient::from_config(sql_cfg).await?;
let rows = db.query("SELECT * FROM users").await?;

CLI 工作流

CLI 覆盖脚手架、proto 生成、开发运行、构建、升级与宠物导出。

  • ecat run --watch 在文件变更时重启。
  • ecat upgrade 改写 ecat-* 依赖版本。
  • ecat pet 导出全部 13 个矢量形态。
terminal
ecat new helloworld
ecat run --watch
ecat build
ecat upgrade

# 浏览形态
ecat pet list

# 输出单个 SVG
ecat pet show smile

# 导出全部 13 个
ecat pet export ./pet
