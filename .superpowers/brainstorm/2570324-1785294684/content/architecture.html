e-cat 整体架构设计（初稿）

对标 Kratos v3，Rust 实现。选择你倾向的架构方案

方案 A：单一 Crate + Feature Flags

单仓库单 Crate 模式
e-cat/
├── src/
│   ├── app.rs          # 应用生命周期（kratos.New / app.Run）
│   ├── transport/
│   │   ├── mod.rs
│   │   ├── http.rs     # axum 集成
│   │   └── grpc.rs     # tonic 集成
│   ├── middleware/      # 中间件抽象层
│   ├── registry/        # 服务注册发现接口
│   ├── config/          # 配置多源加载
│   ├── logging/         # tracing 集成
│   ├── encoding/        # 序列化/反序列化
│   ├── errors/          # 错误码体系
│   ├── metadata/        # 元数据传输
│   └── metrics/         # Prometheus 指标
├── Cargo.toml           # feature flags 控制依赖
└── e-cat-cli/           # 独立的 CLI 工具 crate

优点

  • 简单直观，开发初期快
  • 一个版本号管理所有

缺点

  • 编译慢，改一行编译整个 crate
  • feature flag 组合爆炸
  • 难以独立演进各模块

方案 B：Cargo Workspace 多 Crate

Workspace 多 Crate 模式（推荐）
e-cat/                          # workspace root
├── Cargo.toml                  # [workspace] members
├── ecat/                       # 核心 crate：应用生命周期
├── ecat-transport/             # HTTP + gRPC 传输抽象
├── ecat-transport-http/        # axum 实现
├── ecat-transport-grpc/        # tonic 实现
├── ecat-middleware/            # 通用中间件
├── ecat-registry/              # 服务注册/发现接口
├── ecat-registry-etcd/         # etcd 注册实现（contrib）
├── ecat-config/                # 配置管理
├── ecat-config-file/           # 文件配置源
├── ecat-logging/               # tracing 集成
├── ecat-encoding/              # 编码（JSON/Protobuf）
├── ecat-errors/                # 错误码定义
├── ecat-metadata/              # 元数据传递
├── ecat-metrics/               # Prometheus 集成
├── ecat-protos/                # Protobuf 定义
├── ecat-cli/                   # CLI 工具
└── examples/                   # 示例项目

优点

  • 模块独立编译，增量编译快
  • 版本独立，用户按需引入
  • 类似 Kratos contrib 生态

缺点

  • 初始结构复杂
  • 跨 crate 类型共享需要设计 trait

方案 C：混合模式 — 核心单 Crate + Contrib 多 Crate

核心紧凑 + 扩展独立
e-cat/
├── ecat/                    # 核心：app/transport/middleware/errors/config/logging
├── ecat-contrib/
│   ├── registry-etcd/       # etcd 注册
│   ├── registry-consul/     # consul 注册
│   ├── config-remote/       # 远程配置源
│   └── middleware-auth/     # 认证中间件
├── ecat-protos/             # proto 定义
├── ecat-cli/                # CLI 工具
└── examples/

优点

  • 核心 API 在一个 crate 中，类型共享方便
  • 扩展生态保持独立

缺点

  • 核心 crate 可能膨胀
  • 边界不如纯多 crate 清晰
